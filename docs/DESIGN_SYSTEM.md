# AutoApply 设计规范

界面的样式来源是 `frontend/src/style.css`（令牌、基础元素、旧组件）和 `frontend/src/styles/`（`foundations.css` 文字与基础件、`table.css` 表格、`overlay.css` 浮层、`patterns.css` 业务组合）。页面只使用这里定义的令牌和组件类，不自己写颜色、字号、高度、圆角或阴影。共享组件的名称、属性和保证写在 [`component-guidelines.md`](component-guidelines.md)（英文，是约定，开头有“新页面的规则”清单）；界面文字的用词在 [`ux-writing-glossary.md`](ux-writing-glossary.md)；界面检查（布局测试、`ui-rules` 测试、截图对比）在 [`ui-quality-assurance.md`](ui-quality-assurance.md)。新增页面先看这几份文件，缺什么组件先补到样式和文档里，再用。每个共享组件在 `/ui-lab`（不在导航里）有一节，列出它的各种状态。

## 1. 原则

1. **面向用户，不面向引擎。** 屏幕上不出现内部标识和原始报错：
   - 网站用雇主名加系统名：`TMX · Workday`，不是 `workday:tmx.wd3`。
   - 任务说它在做什么：“读取申请表、生成草案”，不是 `recon`。
   - 出错时给一句话说明发生了什么、需不需要用户做什么；原始报错放进折叠的“技术细节”。
   - 这些转换集中在后端 `backend/autoapply/humanize.py`，接口返回 `site`、`explained`、`label`、`subject` 等展示字段。前端不自己拼内部字段。
2. **每屏一个主要动作。** 一组按钮里最多一个 `.primary`。破坏性操作用 `.danger`，次要操作用 `.ghost`。
3. **先说结论，再给细节。** 卡片的第一行是“发生了什么”，第二行是“为什么 / 你要做什么”，再往下才是操作和细节。
4. **状态用同一套词。** 岗位状态只来自 `backend/autoapply/stages.py`，账号、任务、草案的状态词来自 `humanize.py`。不在页面里另起一套叫法。
5. **键盘和读屏走得通。** 能点的东西是按钮或链接，不是加了点击事件的 `div`；每个控件有名称；盖在页面上的一层接管焦点（第 4 节）；信息不只放在悬停提示或颜色里。
6. **不用内部术语。** 不说 ATS、驱动、侦察、回读、token、租户。对应说法：招聘系统、适配、读取申请表、逐项核对、令牌、网站。

## 2. 品牌

- 标志：`frontend/public/logo-mark.svg`（青色 “A” 加深蓝对勾），完整字标 `logo-full.svg`，网站图标 `favicon.png`。来自旧版 AutoApply。
- 品牌色：深蓝 `--brand-navy #0b1f3a`、青色 `--brand-cyan #12c9bb`。青色只用于标志，不用于界面文字或按钮（对比度不够）。
- 操作色：`--primary #1f4fd8`。

## 3. 令牌

| 类别 | 令牌 | 用途 |
| --- | --- | --- |
| 背景 | `--bg` `--surface` `--surface-2` | 页面底、卡片、次级底（表头、悬停） |

| 文字 | `--text` `--text-2` `--text-3` | 正文、说明、占位和最弱提示（三级都要读得清：见第 7 节“对比度”） |

| 含义 | `--ok` `--warn` `--bad` `--info`，各带 `-soft` 底色；`--on-bad`；`--neutral-soft` | 成功、需要注意、失败、提示；`--on-bad` 是压在 `--bad` 实心底上的文字；`--neutral-soft` 是没有语气的徽标底 |

| 圆角 | `--r-sm 6` `--r-md 10` `--r-lg 14` `--r-pill` | 控件、卡片、大容器、徽标 |
| 阴影 | `--shadow-sm` `--shadow-md` `--shadow-lg` | 卡片、浮层、抽屉和提示 |
| 层级 | `--z-sticky 20` `--z-overlay 40` `--z-drawer 41` `--z-pop 60` `--z-tip 70` `--z-toast 80` `--z-dialog 90` `--z-select 100` | 吸顶吸底的条、抽屉遮罩、抽屉、菜单和气泡、悬停提示、轻提示、必须回答的确认框（遮罩连轻提示一起盖住）、下拉的选项列表（它可能在抽屉、气泡、确认框里打开） |
| 动效 | `--dur-fast 120ms` `--dur 160ms` `--ease` | 悬停和按下、展开的东西 |
| 悬停提示 | `--tip-bg` `--tip-fg` | 与页面反色；对比度在测试里 |

深色模式跟随系统（`prefers-color-scheme`），同名令牌换值，页面不需要单独处理。字体用系统字体，不加载网络字体（应用在本机离线运行）。

### 控件尺寸

同一级的控件在任何地方都是同一个高度；高度是写明的（`height` + `box-sizing: border-box`），不靠内边距凑出来。

| 级别 | 高度 | 用在 |
| --- | --- | --- |
| 默认 | `--h-md` 32 | 按钮、输入框、下拉（`AaSelect`）、分段切换（`.seg`，轨道 3px + 内部按钮 26） |
| 小 | `--h-sm` 28 | `.sm`：`button.sm`、`input.sm`、`<AaSelect small>`；`IconButton` 默认尺寸 |
| 大 | `--h-lg` 36 | `.lg`：少数单独出现的主按钮（登录页） |
| 最小 | `--h-xs` 24 | `IconButton size="sm"`（点击范围仍然不小于 28） |

- 并排的按钮、输入框、下拉、分段切换必须等高：不要给其中一个单独写内边距或高度。筛选栏（`.filters`）里的控件就是默认级，没有自己的尺寸。
- 按钮永不换行（`white-space: nowrap` 在基础样式里）。放不下时由页面决定把次要操作收进菜单，不靠换行。
- 多行的东西不设固定高度：`textarea`、以 `<button>` 实现的行或卡片（材料库的文件行、日程条目）自己声明高度。
- 复选框和单选固定 17px；徽标（`.tag`）固定 20px。

### 字体层级

| 角色 | 字号 / 字重 | 写法 |
| --- | --- | --- |
| 页面标题 | 26 / `--fw-bold` | `PageHead`（`.page-head h2`），每页一个 |
| 小节标题 | 16 / `--fw-semibold` | `h3`、`SectionHead`、`SetSection` |
| 卡片标题 | 15 / `--fw-semibold` | `.card-title` |
| 主信息 | 14 / `--fw-medium`，`--text` | `.t-primary`：一行里说“这是什么”的那句 |
| 次要信息 | 13 / 常规，`--text-2` | `.t-secondary` |
| 元信息 | 12 / 常规，`--text-3` | `.t-meta`；空值的“—”用 `<span class="none">—</span>` |

- 密集区域（表格、列表）的主信息用中等字重，不用粗体；旧表格里的 `<b>` 最多是 `--fw-semibold`。粗体只给页面标题和大数字。
- 上下对齐的数字加 `.num`（等宽数字）。
- 页面和组件里不写像素字号和数字字重，只用令牌或上面的类。

### 文字溢出

| 文字种类 | 规则 |
| --- | --- |
| 按钮、徽标、短标签、日期、时间、数字 | 不换行（`.atomic`，或组件自带） |
| 公司、岗位、网站、文件名 | 单行，放不下时省略号；完整内容在溢出提示里 |
| 域名、邮箱、网址 | 单行省略；正文里不用 `word-break: break-all` |
| 表格里的描述 | 最多两行（`<Trunc :lines="2">`） |
| 段落 | 自然换行 |
| 技术细节 | 不放在行里：放气泡、抽屉或 `TechDetails` |

- 用 `<Trunc :text>`：单行省略，**只有真的被截断时**才出现提示（`v-tip.overflow`）。纯样式写法是 `.cut`（单行）、`.cut2`（两行）；在 flex 或 grid 里，被截断的元素还要能收缩（`min-width: 0`）。
- 截断只是显示方式：数据本身不截，更不按字符数截。
- 给人看的悬停说明走 `v-tip` / `InfoTip`，不用浏览器的 `title`（细则见 `component-guidelines.md`）。

### 层级、动效、焦点

- 浮在页面上的东西只用 `--z-*` 这八级，不写裸数字；同一级之内靠 DOM 顺序。挂在 `<body>` 上的浮层（提示、菜单、气泡）如果是从更高一层里打开的，会自动放到那一层之上（`float.js` 的 `zOver`）。
- 过渡只用 `--dur-fast`（悬停、按下）和 `--dur`（展开、出现），曲线 `--ease`。
- 用户设置了“减少动态效果”（`prefers-reduced-motion`）时，所有过渡和动画立即结束（`style.css` 里一条全局规则）；组件不需要各写一遍，也不要让任何信息只靠动画传达。注意这条规则让**每一个**样式变化都变成一次 0.01ms 的过渡，晚一帧生效：浮层的位置（`left` / `top`）因此必须 `transition: none`（`.tip-box`、`.pop`、`.menu-pop` 已经是），而且要在放好位置之前不可见——用 `opacity`，不用会被子元素继承的 `visibility`（子元素继承的 `visibility` 也会晚一帧，那一帧里拿不到焦点）。
- 焦点环全程序一个：`2px solid var(--primary)`、外扩 2px 的 `outline`，只在键盘操作时出现（`:focus-visible`）。可输入的框（输入框、下拉）是主色边框加一圈 `--focus` 光晕。用 `outline` 而不是 `box-shadow`：它跟随元素自己的圆角，也不和元素的阴影抢。组件不要自己另画焦点样式；`all: unset` 过的按钮照这个样子补回来。

## 4. 组件

| 组件 | 写法 | 说明 |
| --- | --- | --- |
| 页头 | `<PageHead title help sub>` 加操作插槽 | 每页一个。`help` 是标题旁的 (i)：这页是干什么的（确有帮助才写）；`sub` 是标题下一行，只放在这里做决定必须知道的事，多数页面没有。操作在一行里：次要的在前，主按钮在最后；放不下时整组落到标题下面 |
| 小节头 | `<SectionHead title count help>` 加操作插槽 | 页面里的一节：标题、数量、(i)，右侧是这一节自己的操作 |
| 操作组 | `.actions` | 一组操作：一行、等高、间距 8px，不换行 |
| 图标按钮 | `<IconButton icon label>` | 只有图标的按钮。`label` 必填，同时是读屏名称和悬停提示；`size` `md` 28 / `sm` 24，`tone="danger"`，`pressed`（开关），`loading`（原位转圈，大小不变） |
| 截断文字 | `<Trunc :text>`、`.cut`、`.cut2` | 见第 3 节“文字溢出” |
| 状态 | `<Status tone label tip>` | 圆点加文字；见下面“状态的三种轻重” |
| 批量操作栏 | `<BulkBar :count @clear>` 加操作插槽 | 勾选了行才出现，固定在内容区底部居中，不推动页面；依次是“已选 N 项”、操作、“取消选择”。放在页面最外层，不要放进容器查询或有 `transform` 的盒子里 |
| 卡片 | `.card`（`.panel` 同义）加 `.card-title` | 一组相关内容 |
| 按钮 | `button`、`.primary`、`.ghost`、`.danger`、`.sm`、`.lg` | 默认是次要按钮；链接长成按钮用 `.btn`。高度见第 3 节“控件尺寸” |
| 徽标 | `.tag`（`.badge` 同义）加 `.ok .warn .bad .info` | 必须被看见的状态；一个徽标只说一件事。高 20px、单行，所在位置比文字窄时省略 |
| 分段切换 | `.seg > button.on`（链接用 `a.seg-link`） | 筛选分组、视图切换（按钮用 `aria-pressed`）；和按钮等高 |
| 标签页 | `<Tabs v-model :items :label>` | 页内分成几部分时用：一行、放不下时在自己里面横向滚动；方向键、Home、End 切换。外观就是 `.seg.tabs`，不要再手写 `role="tablist"` |
| 卡片头 | `<CardHead title help note>` 加工具插槽 | 卡片的标题、(i)、一句备注、右侧控件；标题放不下时省略，控件整组换到下一行 |
| 帮助 | `<HelpPop text>` 或插槽 | (i) 后面的说明，不管多长：一句话是悬停提示，长了或有链接、列表时自动变成气泡 |
| 菜单、气泡 | `<Menu :items @pick>`、`<Popover>` | 少用的操作、一段说明或小表单；见 `component-guidelines.md` |
| 表格 | `<DataTable :columns :rows>`（单元格 `EntityCell`、`DateTimeCell`、`CredentialCell`） | 列宽由列定义算出，内容撑不开列、撑不高行；窄了先隐藏可选列，再在自己里面横向滚动。旧的 `.table-wrap > table` 只留在 `ui-rules` 测试列出理由的地方 |
| 提示条 | `.callout` 加 `.warn .bad .ok` | 页面内需要注意的一段话 |
| 待办卡 | `.card.todo`：`.ico`、`.title`、`.what`、`.acts` | 图标 + 标题 + 一句说明 + 操作 |
| 列表 | `.list > .item`（左徽标 / 中内容 / 右时间） | 活动、邮件、最近申请 |
| 统计块 | `.stat`：`.n` 数字、`.l` 说明；需要注意时加 `.attn` | 概览页 |
| 空状态 | `<EmptyState icon title text>` | 没有数据时说明原因和下一步，不留空白 |
| 技术细节 | `<TechDetails :text>` | 原始报错、步骤日志；默认折叠 |
| 抽屉 | `<SideDrawer title sub>`（`components/SideDrawer.vue`） | 详情和长列表；不要自己拼 `.overlay` 加 `.drawer`。焦点规则见下面“盖在页面上的一层” |
| 数据状态 | `dataState(read)` + `<DataState :s="st" what @retry>`（`src/data.js`） | 页面读数据的四种状态，见下面“读数据的页面” |
| 动作 | `run(fn, okText, after, { name, form })`（`src/ui.js`） | 所有会改东西的按钮都走它，见下面“做一件事的按钮” |
| 轻提示 | `toast(text, tone, { to, link })`（`src/ui.js`） | 轻量的结果（“已保存”“已排队”）。不是唯一的结果出口：表单的错误留在表单上，读不到数据由页面自己说 |
| 表单错误 | `<FormError name>` | 配合 `run(..., { form: name })`：上一次提交被拒绝的原因留在按钮旁边，直到再次提交 |
| 口径说明 | `<Explain label>文字</Explain>` | 一个数字怎么算的。能点开（鼠标、键盘、触屏都行），不要只放在 `title` 里 |
| 设置小节 | `<SetSection id title how>` | 设置页的一节：有地址（`/settings/<组>/<id>`），标题旁写明怎么保存（`how`: `top` 右上角 / `own` 自己的按钮 / `now` 立即生效 / 空） |
| 选文件 | `<FileButton accept multiple @change>文字</FileButton>` | 真正的按钮加隐藏的文件输入；键盘够得着 |
| 图标 | `<Icon name>`（`components/Icon.vue`） | 统一线性图标；新图标加到这个文件，不在页面里贴 SVG |
| 表单 | `.fields` 网格（`label.f` 标签在上）、`.kv` 两栏、`.field`、`.hint`；按钮行 `.actions.form-acts` | 每个设置项用白话写标签，必要时加一行 `.hint`；细则见 `component-guidelines.md` “Forms” |
| 固定行的列表 | `.rows > .r` | 不是表格的简单列表（`.lead` `.entity` `.end`；`.rows.tight` 40px） |
| Markdown | `.md` 加 `renderMarkdown()` | 个人资料预览 |

### 状态的三种轻重

说“处于什么状态”有三种写法，由重到轻，多数情况用第三种：

1. **徽标** `.tag` / `.tag.ok|warn|bad|info`，以及日程的 `.ev-kind`：对业务重要、必须一眼看到的状态——面试、笔试、逾期、失败、等验证码。一行里最多一个有底色的东西。
2. **`<Status>`**：密集区域里的普通状态——`● 自动登录可用`、`● 会话已保存`。6px 圆点带语气色，文字是 13px 的 `--text-2`；`tip` 给一句简短原因，显示为一个 (i)。
3. **`.meta`**：单纯的属性，没有底色——Workday、Greenhouse、“程序注册的”、“雇主官网”。

- 颜色从不单独表达含义：圆点旁边一定有字。
- 红色只给危险、失败和逾期；绿色只给真正成功的事，招聘流程的推进不全是绿的。
- 没有值显示“—”（`.none`），不留空、不写 0。

### 业务类型的颜色

和申请有关的类型在任何地方都沿用日程的 `--ev-*` 令牌，不另起一套：`interview` 面试、`assessment` 笔试、`deadline` 截止、`offer` 录用、`follow` 补充材料与跟进、`own` 个人日程、`system` 记录与自动化（`calendar.js` 的 `FAMILY`、`views/calendar/look.js`）。写法：给元素加 `.ev-<类型>`，它设置三个变量——`--a` 标记色、`--b` 浅底、`--f` 浅底上的文字；现成的徽标是 `<span class="ev-kind ev-interview">`。表格、详情、列表里出现同一种类型时用同一个类，不要用 `.tag.info` 之类的语气色去近似。

### 按钮与操作

| 操作 | 样子 |
| --- | --- |
| 页面的主要操作 | `button.primary`，页头里一个 |
| 页面的其他操作 | `button`（次要） |
| 行内或卡片里常用的轻操作 | `button.ghost.sm` 或 `IconButton` |
| 很少用的 | `Menu` 里的一项 |
| 破坏性的 | `Menu` 最下面的 `danger` 项，并用 `ask(…, { danger: true })` 确认；红色不出现在每一行上 |

### 表单控件

下面几种控件有产品自己的写法。目的是外观一致，不是回避原生控件：自己画的控件必须保住原生控件本来就有的东西——键盘操作、焦点、名称、读屏能读到的状态；做不到就用原生的。

- 下拉用 `<AaSelect>`（`components/Select.vue`，全局注册）。写法和原生一样，里面放 `<option>`；支持 `v-model`、键盘上下键、回车、Esc、按字母跳转；弹层挂在 body 上，不会被表格或抽屉裁掉。
- 确认用 `ask(text)`（`ui.js`），返回 Promise；文案里有“删除 / 清理”时确认按钮自动是红色。多于“是 / 否”的问题用 `choose(text, choices, cancel)`。不要用 `confirm()`。
- 复选框、单选、数字框、滚动条的外观在 `style.css` 里统一画，模板里照常写 `<input type="checkbox">`。
- 选文件用 `<FileButton>`，不要用 `<label>` 包一个隐藏的输入框（标签拿不到键盘焦点）。
- 几个互斥选项且每个需要解释时，用 `.choice` 卡片组（见 设置 → 材料与回答 → 简历）。
- **标签和控件的关联**：`.kv` 网格里“标签 + 它后面的控件”由 `src/labels.js` 在页面绘制后自动配对（一个控件 → `for` / `id`；一行多个控件或一组按钮 → 以标签命名的 `group`；只有占位文字的独立输入框 → 以占位文字为名）。所以 `.kv` 里照常写 `<label>名称</label><input>` 即可；不在 `.kv` 里的控件要自己写 `for` / `id` 或 `aria-label`。逐行的勾选框写 `aria-label`（“选择 某公司 某岗位”）。
- 排序的表头是按钮：`<th :aria-sort><button class="th-sort">`。一行的名称如果点了会打开详情，它是链接（`a.rowlink`），整行可点只是额外的方便。

### 读数据的页面

页面读服务器数据有四种状态，页面要说清自己在哪一种（`src/data.js`）：

| 状态 | 意思 | 页面显示 |
| --- | --- | --- |
| `loading` | 还没读到过 | “正在读取…”，不显示“0 个”和空状态图 |
| `ready` | 显示的是 `at` 时读到的 | 内容本身 |
| `error` | 没读到过，上一次读取失败 | 说明哪里没读出来 + “重试” |
| `stale` | 之前读到过，后来一次读取失败 | 内容照常显示，上方一条“下面是 HH:MM 读到的，可能已经不是最新的” + “重试” |

写法：`const { st, load } = dataState(read)`，模板里 `<DataState :s="st" what="岗位列表" @retry="load" />`，内容包在 `<template v-if="st.at">` 里。`load` 不抛异常（返回 `true` / `false`），轮询和动作之后的刷新都不用再接错误。

列表什么时候重新读：`useRefresh(load)`——侧栏计数变了、窗口重新被看到时；需要时再加节拍（`{ every, when }`）。不要在页面里自己起定时器。重新读只替换读到的数据，筛选、搜索、勾选、滚动位置不动。

页面“正在看什么”（分组、筛选、排序、打开的那一条、时间范围）写进地址（`src/urlstate.js`：只写和默认值不同的），这样刷新、后退、把地址发给别人都是同一个画面。打开详情是历史里的一步，后退键关闭它。

### 做一件事的按钮

所有会改东西的按钮都走 `run(fn, okText, after, opts)`：

- **只做一次**：动作进行中，被点的那个按钮自动标成忙（转圈、不可点），再点不执行。页面想自己显示状态，或几个按钮共用一把锁时，给动作起名字（`{ name: 'approve' }`，模板里用 `busy('approve')`）。
- **失败和“做完了但没刷新出来”分开说**：动作本身失败，说失败原因；动作成功、之后重新读取失败，说“已经做完了，但页面没能读到最新的内容”（用了 `dataState` 的页面由过期提示条来说）。
- **排了队的事说清楚去哪看**：接口返回 `task_id` 时，提示里带“看它排在哪”的链接（工作计划）。
- **表单的错误留在表单上**：`{ form: 'settings' }` 加 `<FormError name="settings" />`。九秒后消失的提示不是“端口被占用”这种信息该待的地方。

没保存的输入：一个编辑区用 `useUnsaved({ id, label, dirty, save, discard })` 登记自己（`src/dirty.js`）。离开页面、刷新、切换编辑对象时统一询问“保存 / 放弃改动 / 继续编辑”，没有改动时不问。重新读取数据时用 `absorb`：只更新没在编辑的字段，不冲掉正在输入的内容。

### 盖在页面上的一层

抽屉、确认框、窄屏的导航菜单打开时接管键盘（`src/focus.js` 的 `hold(el, { first })`）：

- 焦点进入这一层；默认落在层本身（读屏会读出它的名字），确认框落在该按的按钮上——**不可撤销的操作落在“取消”上**，不落在“删除”上；
- Tab 圈在这一层里；背后的页面设为 `inert`，够不着也点不到；
- Esc 只关最上面那一层（确认框盖在抽屉上时，关的是确认框）；
- 关闭后焦点回到打开它之前的位置；
- 换页之后焦点落在新页面的标题上。

新写的浮层用 `SideDrawer` 或 `hold`，不要自己监听 Esc。

## 5. 文案

- 用“你”称呼用户，用“程序”或“AI”指代系统，不用“agent”。
- 按钮写动作和对象：“我有账号，去登录”“重新填写并提交”，不写“确定”“执行”。
- 时间用 `fmtTime()`：今天 / 昨天 / 几月几日。服务器时间是不带时区的 UTC，统一由 `fmtTime` 和 `fmt` 转成本地时间。
- 申请表上的原文（问题、选项、要填的英文答案）保持原样；对它们的解释用中文。模型输出里给用户看的说明字段（依据、评分理由、邮件摘要）在提示词里要求用中文。

## 6. 页面结构

导航分三组：日常（概览、需要我处理、日程、岗位、申请）、我的资料（个人资料、材料库、人脉与内推、网站账号）、系统（数据分析、活动记录、设置、关于）。来源与关注公司从岗位页进；等你批准的申请记录在申请页的“要我处理”里，记录本身在每份申请的页面上。

窄屏（内容区 ≤ 1000px）：侧栏收成一条顶栏——当前页名、待办数量、运行状态、“菜单”；完整导航、主题、语言、暂停在菜单里。宽表格在窄屏下只留“是什么、到哪一步、要注意什么”的列（其余列加 `.col-more`）。

岗位表固定五列：评分、岗位（公司 / 标题 / 地点·学期·时长合在一格）、截止、状态、最新情况。来源、方向、薪资、在哪里投、发布日期、发现日期是可选列，由“显示的列”开关控制，选择存在浏览器里。原则：固定列回答“是什么、好不好、急不急、到哪一步”，其余细节放抽屉。已归档的岗位默认不显示。

材料库是三栏：文件夹（我上传的 / 为岗位生成的 / 全部）、文件列表、预览。岗位的文件夹分两行显示（雇主 / 标题·地点·学期），同一家的几个岗位才分得开。列表里文件名是“打开”按钮，勾选框是另一个控件。PDF 用 pdf.js 画在 canvas 上，文件以普通二进制读取，不经过 iframe，这样下载管理器（IDM 之类）不会把预览截走；容器宽度变了会重新适配，新的一次绘制会取消旧的。Word 文件先由本机 Word 转成 PDF 再预览。

草案详情：完整的问答表格上方先列“先看这几项”（没答案的、第一次遇到的敏感问题、把握不高的、表单变化后改过的、为这个岗位写的材料、由谁提交及原因），每项跳到对应的行。

数据分析页是同一个时间范围下的四个视图：求职成效、自动化效率、耗时与优化、AI 成本。时间范围（全部 / 最近 90 天 / 最近 30 天 / 最近 7 天 / 今天 / 自定义日期）各视图共用，视图和时间范围都写在地址里（`?view=ai&range=30`）。口径：

- **“已投出”在所有页面是同一个数**：处于“已提交”或之后任何一步的全部申请（概览、我的申请、分析页）。某一页只显示其中一部分时，写明是哪一部分、差多少：概览的阶段图不含岗位已归档的，分析页不含没有投递日期的。
- 说一份申请“后来怎样”只用三个词，并且在一处计算（`analytics.came_of`）：**收到回执**（对方有过任何回应，含自动确认信）、**有实质结果**（进入过笔试或面试，或者被拒；自动确认信不算）、**进入笔试 / 面试**。不要再用“有回音”“有明确结果”。少于 5 个申请的分组只列数量、不显示比例。
- 任务的成功率不是申请的结果：“填写申请表”的一次成功，指这一次运行把申请提交出去了；发现申请早已投出而什么都没做的任务两边都不算；“点了提交、结果待确认”单列。
- 每个数字只用一种日期：申请按投出日，回复按到达日，任务按开始日，模型请求按发生日。两种日期出现在同一处时写明。
- “不知道”不是 0：算不出的费用显示为“—”，下限显示为“≥”，并说明原因。
- KPI 卡片放数字、名称和（有上一段可比时）变化；口径用 `<Explain>` 放在卡片里，点开看。悬停提示（`title`）只用来补充鼠标用户顺手能看到的东西，不承载别处没有的信息：触屏和键盘看不到它。
- 版面是一行一行的卡片（`.an-row`）：一行有多高由这一行的内容决定，同一行的卡片顶边和底边对齐，不同行各不相同。列宽由行决定（`.c11` 一比一、`.c32` 三比二、`.c21` 二比一），卡片只管内容。没有固定高度；卡片被拉高时图表保持自己的高度，多出来的空间落在卡片页脚（`.card-foot`）上面。断点按页面内容区的宽度判断（容器查询），不按窗口宽度：内容区窄于 1040px 时不等宽的行变成一栏，窄于 900px 时等宽的行也变成一栏。
- 概览和明细分两层。概览卡片不会因为展开明细而变高：
  - 同一份数据的两种看法（图 / 表）在卡片里二选一，不上下堆叠；
  - 图表背后的数字在这一行下方打开一个全宽面板（`DetailPanel` + `SeriesTable`），收起后版面恢复原样；
  - 长列表和单条记录在抽屉里看（`SideDrawer`）：概览只放前几条和“查看全部”。
- 可能很长的表格都分页（`Pager`），不用固定高度加隐藏溢出来藏数据。
- 按类别比大小的横条用 `.hbars.even`：标签列、条、数字列宽度固定，同一行两张卡片的条从同一位置开始；标签过长时省略，完整文字在悬停提示里。

侧栏底部显示当前在做什么，以及暂停开关。

设置页按用户要决定的事分成六组，不按内部模块：求职目标与匹配、自动化与工作计划、材料与回答、账号与连接、通知与提醒、系统与数据。每组是一页，由若干有名字、可直接链接的小节组成（`/settings/<组>/<节>`，`SetSection`）；每节写明怎么保存。重要的能力不因为“高级”而藏起来：不常用、需要理解内部机制的选项放在所属小节的展开层里。日常要看的对象（关注的雇主、上次扫描）不放在设置里。

## 7. 主题

外观有三档：浅色、深色、跟随系统，在侧栏底部切换，选择保存在浏览器里（`src/ui.js` 的 `setTheme`）。实现方式是给 `<html>` 加 `data-theme`；没有这个属性时跟随系统。深色令牌在 `style.css` 里写了两处（系统深色、手动深色），改的时候两处一起改；新增的颜色令牌两处都要有，值相同（对比度测试会核对两处是否一致）。

深色模式下标志垫一块白色圆角底（`--logo-tile`），否则深蓝色的对勾看不见。

**对比度**：读的文字对它所在的底色至少 4.5:1，两套主题都是。`frontend/tests/contrast.test.js` 直接从 `style.css` 读令牌，逐组核对（三级文字 × 三种底色、状态色 × 各自的浅底、主色上的文字、悬停提示的 `--tip-fg` × `--tip-bg`……），改令牌后跑 `npm test` 就知道有没有掉下去。最弱的一级文字（`--text-3`）也是文字，不是装饰。

**压在颜色上的文字用专门的前景色令牌**，不要写死 `#fff`：主色上用 `--on-primary`，红色上用 `--on-bad`（侧栏计数、错误提示、“删除”实心按钮）。深色主题里 `--bad` 是浅红，白字压上去只有 2.1:1。以后给别的状态色做实心底时，同样先加 `--on-…` 令牌并把这一组写进对比度测试。

## 8. 图表

规则来自 dataviz 方法：先定形式，颜色最后定。

- 单系列图表用 `--chart-1`（浅色 `#2a78d6`，深色 `#3987e5`）。单系列不放图例，标题说明画的是什么。
- 多系列用 `--chart-1` … `--chart-6` 这六个色，顺序固定、不循环：蓝、橙、青绿、黄、品红、绿。第七个系列并入“其他”（`--chart-other`，中性灰）。这组颜色在本产品的浅色底（`#ffffff`）和深色底（`#151d29`）上都用 dataviz 的校验脚本整组验过（相邻色的色觉障碍区分度、普通视觉区分度、明度带）。浅色下第 3、4、5 色对底色的对比度不到 3:1，所以多系列图必须有图例和“用表格看”。
- 两个或更多系列必须有图例；图例上的文字和数字用文字令牌。`StackChart` 的图例可以点：把一个系列从图里拿掉或放回来。
- 一张图一个坐标轴、一个单位。成本和 Token 用开关切换，不画双轴。
- 状态（完成 / 没做完 / 失败）是状态，不是系列：用 `--ok` / `--warn` / `--bad`，并且总带文字。有先后的状态（没有回音 → 自动确认 → 笔试 → 面试）用同一色相由浅到深：`--chart-soft`、`--chart-1`、`--chart-deep`。
- 堆叠的各段之间留 2px 底色缝隙，不描边。
- 柱子最宽 24px，数据端 4px 圆角，从同一条基线长出来；网格线是 1px 实线，颜色 `--chart-grid`。
- 不给每根柱子都标数字：只标最高的和最后一根，其余靠坐标轴和悬停提示。
- 图表下面都有“用表格看”，悬停有提示。
- 文字用文字令牌，不用数据色。状态色（成功、警告、失败）不拿来当系列色。
- 组件：`ColumnChart.vue`（随时间变化的一个数量）、`StackChart.vue`（随时间变化、分成几部分的数量）、`SplitBar.vue`（一个整体分成几部分，带图例）、`.hbars`（按类别比大小）、`SeriesTable.vue`（图表背后的数字，分页）、`DetailPanel.vue`、`SideDrawer.vue`、`Pager.vue`。
- 要换色板时，先按 dataviz 的流程选色并整组跑校验脚本，再改令牌，不要临时挑颜色。

### 日程（`CalendarView.vue`、`views/calendar/`）

- 事件按类型着色，令牌 `--ev-<类型>`（标记色）、`--ev-<类型>-bg`（浅底）、`--ev-<类型>-fg`（浅底上的文字），类型有 `deadline` `interview` `assessment` `offer` `follow`（补充材料、联系跟进）`own`（个人日程）`system`（记录与自动化）。深色模式各有一套，不复用浅色的底。`-fg` 在 `-bg` 和 `--surface` 上都要 4.5:1（`tests/contrast.test.js`）。
- 颜色只说“是什么”；“处于什么状态”用文字、删除线和变弱的文字说（已完成、已过、已截止、已投递）；“多重要”用位置说（`calendar.js` 的 `rank`）。红色只给真正要警示的：逾期未处理。普通截止不是红色。
- 每种类型还有一个图标（`look.js` 的 `GLYPH`），不只靠颜色区分。
- 月格按格子的实际高度决定放几行：重要的单独一行，当天其余截止合成一行“N 项申请截止”，放不下的合成“+N 项日程”；同一条不会既单独显示又被计数。周视图的截止放在顶部的全天条里，不占时间轴。
- 详情面板在宽度够时放在日历右侧（360px），不够时从右侧盖上来（和抽屉一样持有键盘焦点）。
